# Research experiment layout

Each substantive experiment belongs on its own `research/<question>` branch and should open a Draft Research PR early.

Recommended experiment directory:

```text
research/<experiment-id>/
  PREREGISTRATION.md
  fixtures/
  controls/
  target/
  raw/
  scores/
  receipts/
  deviations/
  terminal/
```

The exact shape may vary, but the evidence responsibilities should not.

## Before decisive execution

Record:

- exact research question;
- inherited evidence and what is only hypothesis;
- competing explanations;
- smallest discriminating test;
- target architecture and controlled variables;
- weak controls;
- hard falsifiers;
- positive burden;
- exact repository/ref/blob identities;
- independence and adjudication limits;
- explicit non-claims;
- terminal vocabulary.

Freeze promotion-critical target and evaluator bytes before creating or exposing the fresh decisive surface wherever practical.

## During execution

Preserve raw outputs before scoring. Keep gold/expected dispositions outside runtime authority. Record exact replay and mutation/metamorphic results. Do not delete failed runs or harness deviations.

## Terminal record

Use exactly one project research disposition when the question reaches a stopping point:

- `SUPPORTED FOR PROMOTION`
- `FALSIFIED`
- `INCONCLUSIVE`
- `SUPERSEDED`

A green workflow is not a scientific disposition.

Terminal records should include exact frozen identities, observed results, decisive counterexamples, deviations, weak-control results, residual uncertainty, non-claims, and the smallest authorized successor or promotion action.

## Separation rule

Research implementations are evidence records. Do not merge a successful research branch wholesale as production. If evidence eventually supports pipeline insertion, open a new minimal promotion PR from the real production base containing only the capability justified by the evidence.
