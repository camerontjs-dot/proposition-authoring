# S0-R2 cold-review diagnostic

## Question and predecessor

Can a prospective maximal-predication rule settle annotation grain while cold
reviewers continue to preserve material scope alternatives? S0-R0/R1 gave one
ATOMIC versus UNRESOLVED_REVIEW disagreement on a rate/direction predication.
Their preloaded background memory also prevents a claim of fully context-free
review. Their raw outputs and terminal limits remain preserved.

The highest-weight assumption is that cold model review can discriminate grain
from truth-condition ambiguity sufficiently to create a working oracle. It is
falsified for this packet by a wrong constructed control, a material unresolved
disagreement, a lost operator/qualifier, or incomplete/invalid model output.
Agreement alone is not proof of semantic correctness.

## Frozen subject and surface

Freeze this directory before inference. Twelve new pre-existing NASA roots are
the fresh public diagnostic cohort. Two public replay anchors test the identified
failure family; they are not fresh cases. Six synthetic adversarial controls
have independently constructed expected classes and remain a separate group.
No root is selected from Gate output. No Gate/runtime output has been generated.

No claim of broad capability or naturalistic prevalence follows from this small
source family. The separately frozen naturalistic sampling definition and the
28-case hostile decomposition suite remain preparation for later stages.

## Reviewer isolation and apparatus

Use existing local Ollama models gemma3:12b and qwen3.5:9b, with model digests,
runtime version, prompt, JSON schema and settings pinned in this directory.
Each request receives exactly the annotation rule, id, root and authorized
context. It receives no source URL, class expectation, development transcript,
memory, proposal, other review or downstream result. No returned context is
reused. The models have no tools or filesystem inputs. This is transport-level
input isolation; it is not proof of independent model training or human review.

Run each reviewer once in frozen order. Preserve raw HTTP response bytes,
request bytes, parse/schema results and runtime failures. Do not retry a failed
or unfavorable completion. Continue the other frozen reviewer for diagnostic
comparison after one reviewer fails; no positive gate remains available.

Repeat R01 and C03 exactly once under each model as preregistered replay
measurements. Temperature zero and seed 58 do not establish provider-guaranteed
determinism. Compare annotation/content separately from timing metadata.

## Evaluation and stopping rule

Check required fields and row identity mechanically. Compare class and content
obligations without majority voting. Synthetic control expectations are not
supplied to reviewers. Preserve every reviewer-specific annotation before
coordinator adjudication. Adjudication may inspect only the root, rule and raw
review; it may not consult Gate behavior or rewrite a completed review.

Allowed dispositions: SUPPORTED_BOUNDED_COLD_REVIEW_DIAGNOSTIC,
FALSIFIED_COLD_REVIEW_ORACLE, INCONCLUSIVE_ANNOTATION_GRAIN, FAILED_APPARATUS.
Any hard control error or unresolved material disagreement prevents a supported
disposition. Record reasons per case. A supported diagnostic is not the canonical
issue-60 S0 freeze and does not authorize decisive S1 execution by itself.

If falsified, next test the smallest general failure family with a separate
preregistered diagnostic. Do not tune this frozen prompt or replace its cases.
If the annotation rule needs a product-responsibility decision, identify the
specific semantic choice and preserve alternative faithful structures.

## Boundaries

Production runtime, released Contract A, V1, RC0, RC1, programme freeze and the
parallel issue-60/PR-61 scaffold stay unchanged. New authority remains unbuilt.
